Algorithmic Methodology & System Architecture

Formal mathematical formulation and system pipeline details for proportional expense allocation.

1. Multimodal Extraction & Schema Enforcement

Receipts are ingested via multimodal vision encoders and mapped into strict Pydantic v2 data structures (BillItem, BillTaxes, BillMetadata, ParsedBill). Every field is assigned a confidence metric $c \in [0.0, 1.0]$.

class BillItem(BaseModel): id: str name: str quantity: float unit_price: float total_price: float confidence: float

2. Epistemic Discrepancy Verification

Rather than blindly trusting vendor arithmetic, the parser calculates the expected grand total:

$$G_{\text{expected}} = S_{\text{food}} + T_{\text{CGST}} + T_{\text{SGST}} + T_{\text{VAT}} + C_{\text{service}} + C_{\text{other}} - D_{\text{discount}}$$

If $|G_{\text{printed}} - G_{\text{expected}}| > 1.00$, the receipt is flagged with is_arithmetically_valid = False and displays an alert indicating cashier calculation error.

3. Proportional Fair-Share Allocation

For each participant $m_i$, individual food subtotal $S_i$ is computed from shared dishes:

$$S_i = \sum_{k \in \text{Items}_i} \frac{P_k}{N_k}$$

Where $P_k$ is the line item price and $N_k$ is the count of participants sharing item $k$. The participant's spend ratio is:

$$r_i = \frac{S_i}{\sum_{j=1}^{M} S_j}$$

Taxes and charges are allocated strictly according to $r_i$:

$$\text{Total Payable}_i = S_i + (T_{\text{total}} \cdot r_i) + (C_{\text{service}} \cdot r_i) - (D_{\text{discount}} \cdot r_i)$$

4. Penny Residual Reconciliation

Due to floating-point truncation to 2 decimal places, rounding error $\delta$ is computed:

$$\delta = G_{\text{printed}} - \sum_{i=1}^{M} \text{Payable}_i$$

The residual $|\delta| \le 0.05$ is reconciled onto the highest-value subtotal ticket, guaranteeing a zero-residual exact penny balance.
